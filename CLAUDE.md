# wsl-transdebian

A static [reprepro](https://manpages.debian.org/bookworm/reprepro/reprepro.1.en.html)-managed
Debian/Ubuntu apt package repository for WSL-specific packages, served via GitHub Pages at
`https://arkane-systems.github.io/wsl-transdebian/apt/`.

There is no application code, build system, or test suite. Publishing is fully automated via
GitHub Actions; almost all changes to `apt/` arrive as bot commits ("Update apt repository"),
not hand edits.

## Repository layout

- `apt/` — the live repository tree served by GitHub Pages. **Do not edit files here manually**;
  they are managed by `reprepro` via the publish workflow.
  - `apt/conf/distributions` — reprepro distribution definitions, one stanza per codename
    (architectures, signing key fingerprint, description)
  - `apt/conf/incoming` — reprepro incoming config; `Allow:` lists the codenames a single
    `includedeb` run may target (`multiple_distributions` option)
  - `apt/pool/main/<letter>/<source>/` — Debian pool layout for `.deb`, `.dsc`, and `.tar.xz`
    files, keyed by the source package's first letter
  - `apt/dists/<codename>/` — auto-generated `Packages`, `InRelease`, and `Release` files
  - `apt/db/` — reprepro's internal state database; never touch this
  - `apt/wsl-transdebian.gpg` / `.asc` — public GPG signing key (fingerprint `428AD1A0BA078ABB`)
- `updates/` — drop new `.deb` packages here (via PR) to have them ingested on the next push to
  `master`

## Publishing workflow

Defined in [.github/workflows/main.yml](.github/workflows/main.yml), triggered on push to
`master` or manually:

1. A contributor forks the repo, places one or more `.deb` files in `updates/`, and opens a PR.
2. On merge to `master`, the workflow installs `reprepro`, imports the signing key, and for each
   supported distro runs `reprepro --ignore=wrongdistribution -b apt includedeb <distro> <deb>`
   for every package found in `updates/`.
3. It then deletes the processed `.deb` files from `updates/`, commits the updated `apt/` tree
   and cleared `updates/` as `github-actions[bot]`, and pushes to `master`.
4. GitHub Pages serves the updated `apt/` directory immediately — there is no separate deploy
   step.

Required repository secrets: `TRANSDEBIAN_REPO_SIGNING_KEY` (armored private key),
`TRANSDEBIAN_REPO_PASSPHRASE`. The workflow uses the default `GITHUB_TOKEN` for the push (no PAT
needed).

A second workflow, [.github/workflows/cleanup-runs.yaml](.github/workflows/cleanup-runs.yaml),
prunes workflow run history nightly and is unrelated to publishing.

## Supported distributions and architectures

| Codename   | Distribution         | Status      |
|------------|-----------------------|-------------|
| `buster`   | Debian 10              | Supported   |
| `bullseye` | Debian 11              | Supported   |
| `bookworm` | Debian 12              | Supported   |
| `trixie`   | Debian 13               | Supported   |
| `sid`      | Debian (testing)       | Supported   |
| `bionic`   | Ubuntu 18.04 LTS        | Supported   |
| `focal`    | Ubuntu 20.04 LTS        | Supported   |
| `jammy`    | Ubuntu 22.04 LTS        | Supported   |
| `stretch`  | Debian 9                | Deprecated (no longer updated) |

`apt/conf/distributions` declares `amd64` and `arm64` as valid architectures per codename, but
the publish workflow's `includedeb` step only ever ingests whatever architecture the uploaded
`.deb` file itself declares — most packages currently in the pool are `amd64`-only.

## Key conventions

- **Pool naming**: packages follow the Debian pool layout —
  `pool/main/<first-letter-of-source>/<source-name>/<package>_<version>_<arch>.deb`.
- **Git LFS**: `*.tar.gz` files under `apt/` are tracked via Git LFS (see
  `apt/.gitattributes`). Ensure LFS is set up before working with the repo locally so those
  blobs pull correctly.
- **Never hand-edit `apt/dists/` or `apt/db/`** — both are fully regenerated by `reprepro` on
  every publish run and any manual change will be overwritten (or will desync the reprepro
  database) on the next push.
- **Adding a new distro** requires three coordinated edits: add a stanza to
  `apt/conf/distributions`, add the codename to the `Allow:` line in `apt/conf/incoming`, and
  add it to the `distro` loop in `.github/workflows/main.yml`.
- **Kernel packages**: `linux-upstream` source packages (kernel headers/image) are added
  regularly as new WSL2 kernel builds ship; these are typically the only manual, recurring
  contribution pattern in this repo (see git log for examples such as "Added WSL kernel
  ...to updates.").
